- Built and independently smoke-tested all four planned modules, one at a time, each reviewed by Saif before moving to the next:
  1. **`src/router.py` — `LearnedGateRouter`**: per-token gate in (0,1) via a small linear/MLP head; zero-initialized last layer biased so gate starts near 0.88 ("continue"), so router decisions aren't arbitrary before the base model has learned anything. Smoke test caught a real, non-obvious consequence of this init: `x.grad` is exactly zero on the very first backward pass (the zero weight matrix blocks the chain rule into `x`), while the router's own weight still gets a valid gradient — expected bootstrap behavior, not a bug, but the first draft of the test wrongly asserted the opposite and had to be corrected.
  2. **`model.py` extension — `AdaptiveBlock` / `AdaptiveTransformer`**: `AdaptiveBlock` reuses the existing `Block` class unchanged, blending its output with the router gate (`x_new = gate*block(x) + (1-gate)*x`, a highway-style blend — full attn+MLP skip, matching Fork 1). `AdaptiveTransformer` mirrors `BaselineTransformer`'s architecture/init exactly (deliberately duplicated rather than refactored via inheritance, to keep the already-validated baseline code untouched) and returns `(logits, loss, aux)` where `aux` carries per-layer gates and `avg_depth` (each token's summed gate across layers, batch-averaged — the "effective layers used" metric). Caught a real integration bug during smoke-testing: `AdaptiveTransformer`'s blanket `self.apply(_init_weights)` pass re-initializes every `nn.Linear` it finds, including each router's — this would have silently destroyed the router's Module-1 zero-init bootstrap. Fixed by extracting that init into a re-callable `router.reset_gate_init()` and calling it again, per-block, after the blanket pass — verified via the smoke test's exact `avg_depth == 0.88 * n_layer` check at init. Also reran the original baseline smoke test to confirm zero regression from editing the shared `model.py` file.
  3. **`src/losses.py` — `adaptive_loss()`**: quadratic penalty pulling the batch's *average* effective depth toward a `target_avg_layers` config value (`AdaptiveConfig` gained `target_avg_layers`/`budget_weight`), since the LM cross-entropy alone never rewards using fewer layers. Deliberate design choice: penalizes the batch AVERAGE depth, not each token's individual depth — a per-token penalty would push every token toward the same depth, directly contradicting the project's core premise that depth should vary by token difficulty. Verified with pure math checks (zero penalty at target, correct gradient sign both directions) and a real integration test: a tiny model trained on purely random data for 40 Adam steps had `avg_depth` move from 2.64 to 1.34 toward a target of 1.0 — the budget pressure measurably moves real model behavior, not just gradients on paper.
  4. **`src/train_adaptive.py`**: mirrors `train.py`'s structure and reproducibility discipline exactly, wires in `AdaptiveTransformer` and `adaptive_loss`. Log format keeps `"train"`/`"val"` keys holding the total (LM + budget) loss — same key names the baseline log uses — so existing/future plotting code needs no changes for the primary curve; added `train_lm`/`val_lm` and `train_avg_depth`/`val_avg_depth` as new keys.
